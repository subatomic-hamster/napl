# Thrust-stand validation (N4)

Generated by `napl bench all` (python/napl/bench.py). Do not edit by hand.

## Method and what is a prediction

- Stand: welded stator, rotor hinge with prop inertia (+ motor bell as dof armature), one regulated PSU (series R 0.001 ohm; vendors test on a regulated supply; voltage set PER ROW from the table so recorded sag is honoured), ESC + BLDC + rotor devices, still air, ISA sea level (rho 1.225), ground effect off, gravity off, winding held at the steady-state temperature of each row (thermal section below).
- **Fixed from datasheet (not fitted):** kv, winding R (at 20 degC), I0 (constant friction torque Kt I0, see the loss-split scan), prop diameter. Inertias only affect settling time. Estimated inertias are flagged in `build/bench/<motor>.json`.
- **Fixed from literature (not fitted):** the Reynolds / rotor-speed factors f_T(x), f_Q(x), x = n D^2, pooled from the static C_T / C_P vs rpm tables of 7 UIUC APC props (table and equations below). C_T0 / C_Q0 are the coefficients at x = 4.5 m^2/s.
- **From a datasheet temperature (one number per table, not per row):** the winding-to-ambient resistance r_th, calibrated so the model winding at the 100 % row equals the vendor-printed motor temperature (below).
- **Fitted** on 3 rows (first, middle, last throttle) by Levenberg-Marquardt: static prop C_T0 and C_Q0 (no measured coefficients exist for these exact props; `holybro-1045-prop`'s ct_static/cq_static were derived from the very same table so they are NOT used), and the ESC throttle-to-duty map `duty = a*throttle + b` (b only when the table has rpm). Fitted values are written to `build/bench/*.json`, never to parts/.
- **Predicted (held-out):** thrust, current, rpm, power at every other row. Training rows are in the JSON but excluded from the table below. Errors are simulated stand vs vendor table, |sim-vendor|/vendor.
- Power column: electrical V*I where the vendor column equals V*I; the T-MOTOR C-series tables (2807, 2814, 3110, 4214) list shaft power (matches torque*rpm, not V*I), so those are compared on shaft power.

## Reynolds / rotor-speed factor (literature shape)

`C_T(J, n) = C_T(J) f_T(x)`, `C_Q(J, n) = C_Q(J) f_Q(x)`, `x = |n| D^2` (rev/s m^2), piecewise linear, clamped at the ends (rotor device fields `re_x`, `re_ft`, `re_fq`; absent = off). Re at 0.75 R is `rho (2 pi n) (0.75 R) c / mu`, so for blades of equal chord ratio c / D in the same air Re is proportional to `n D^2`: a smaller prop needs a proportionally higher rpm to reach the same Re (the diameter scaling). Assumptions: APC-like section chord ratio and blade-section Re behaviour for every prop (the T-MOTOR / Gemfan / Holybro props are different blades, so the table transfers only the generic trend); static (J = 0) data only, so no J-dependence of the Re effect; the effect is clamped beyond the measured x range; no Mach or flexibility effect. Source: `uiuc-apcsf-8x3.8`, `uiuc-apcsf-9x4.7`, `uiuc-apce-9x4.5`, `uiuc-apce-11x7`, `uiuc-apce-14x12`, `uiuc-apce-17x12`, `uiuc-apc-sf-10x4.7` `[tables.static_ct_cp]` (UIUC Propeller Database vol. 1). Per prop f_i(x) = C(x) / C(x_ref), x_ref = 4.5 m^2/s; pooled by the median of ln f_i over the props covering x (>= 2), re-normalised to f(x_ref) = 1. Fitted parameters added: none.

## Thermal (stand at steady winding temperature)

Used: the device thermal equation at rest, `T = T_amb + r_th I_m^2 R(T)` (copper loss; fixed point with `R(T) = R20 (1 + 0.00393 (T - 20))`, T_amb = 25.0 degC), evaluated per row by the closed form; the stand device is initialised at that T with its own thermal dynamics frozen (c_th = r_th = 1e6), so the stand's R(T) is the device's. Running each row for minutes instead was not done (6 s rows; the steady state is the same fixed point). r_th is one number per table: (T_vendor - T_amb) / (I_m^2 R(T_vendor)) with I_m of the fitted model at the 100 % training row and T_vendor the vendor-printed motor (surface) temperature, transcribed from the part files into `VENDOR_TEMP_C` (surface temperature taken as winding temperature: the winding is hotter, so r_th is a lower bound; mn2806's is after 10 min at 80 %). No per-row parameter. The fit is re-run twice with the calibrated r_th (fit -> r_th -> refit).

## Motor loss law (speed-dependent I0): implemented, rejected by the training rows

Device: `tau_loss(w) = Kt I0 [(1 - v - q) tanh(w / w_s) + v w / w0 + q w |w| / w0^2]`, `w0 = (V_test - R I0) / Ke` (shaft speed at the datasheet I0 test voltage), `v` = viscous share (bearing grease, hysteresis iron loss ~ w), `q` = quadratic share (windage, eddy current ~ w^2); `v = q = 0` is the original Coulomb friction. A one-point datasheet I0 fixes only the sum, so the split `(v, q)` is a global choice, not a datasheet value; no part gives I0 at a second voltage, so there is no two-point case. The split was chosen by the pooled TRAIN-row cost of all tables (re + thermal on), never from held-out rows:

| viscous share v | quadratic share q | pooled train cost | (info) held-out mean thrust % | (info) held-out mean current % |
|---|---|---|---|---|
| 0.0 | 0.0 | 0.741 | 5.98 | 5.29 |
| 0.1 | 0.0 | 0.764 | 6.12 | 5.28 |
| 0.25 | 0.0 | 0.814 | 6.36 | 5.28 |
| 0.5 | 0.0 | 0.943 | 6.80 | 5.35 |
| 1.0 | 0.0 | 1.362 | 7.89 | 5.51 |
| 0.25 | 0.25 | 0.989 | 6.96 | 5.64 |

Adopted: v = 0.0, q = 0.0. Pooled train cost is minimal at v = 0.0, q = 0.0. Inference, not tested: a speed-growing loss lowers the predicted current at low speed, where the C-series tables are already under-predicted, so the missing low-throttle current is more likely the ESC / wiring quiescent draw and the throttle-to-duty offset of the vendor rig (not recorded) than motor iron / bearing loss.

## Fidelity limits and likely causes of error

- I0 is a constant friction torque (the speed-dependent split is implemented but not supported by the train rows, see above).
- The Reynolds factor is a generic APC-prop trend (about +5 % C_T from x = 4.5 to 7.6; the 2216 stand covers x = 4.3 to 10.6), clamped beyond the covered range; the 2216's own table rises 0.089 to 0.096 (+8 %, mostly below ~7000 rpm), so part of its rpm drift remains in the held-out residuals (props differ: the nylon / glass-fibre Holybro blade also flexes).
- Winding temperature comes from a vendor SURFACE temperature (a lower bound for the winding) and a copper-loss-only heat balance; iron loss heating and the ~10 min soak times of the vendor tests are not modelled.
- Tables without an rpm column (xing2 2207 pairs) cannot separate C_T0 from the duty slope; the fit there uses a weak log-normal prior (C_T ~ 0.10, C_Q ~ 0.0065, factor 1.65) and b fixed 0, so the fitted C_T0/C_Q0/a are not individually meaningful; only thrust/current predictions are checked.
- ESC losses, wire and connector resistance of the vendor rig are not recorded; they are absorbed into the duty map and C_Q0.
- Vendor table voltages are as printed; where the printed voltage is a no-load figure, sag is unrecorded.

## X500 V2 hover estimate (open loop, 2216 fit)

- AUW 1.547 kg (assemblies/x500v2.toml build report mass.total); per-motor thrust 3.79 N; avionics 0.146 A from the battery (the assembly's constant-current loads {'load_fc': 0.1083, 'load_gps': 0.0124, 'load_sik': 0.0258}); battery OCV lipo-cell-ocv-chen2006 x 4 cells.

- Endurance to cutoff: **23.6 min** (4850 mAh used; stop: pack terminal voltage < 14.0 V (3.5 V/cell, under load)); to 80 % depth of discharge (SoC 0.2): **20.4 min**. Holybro: "Flight time: ~18 minutes hover with no additional payload. Tested with a 5000mAh Battery." (docs.holybro.com PX4 Development Kit X500v2, Mechanical Specification; AUW, cutoff voltage and battery model not stated). Vendor-table motor current at this thrust 2.99 A (16 V).
- Uses a thrust governor in place of the flight controller; the prediction rests on fitted C_T/C_Q/duty map (2216 + T1045 table at 16 V), estimated battery R / RC (the assembly's, in the parts DB); it is not validated against a flight log. The measured comparison with a PX4 flight of the assembly itself is docs/validation/x500-hover.md.
